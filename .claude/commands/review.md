对当前变更（已暂存或最近提交）进行五维代码评审，输出结构化报告，包含文件和行号定位。

**五个评审维度**：

1. **正确性** — 实现是否符合规格说明？边界情况是否处理？测试是否充分覆盖核心路径？
2. **可读性** — 命名是否表意清晰？逻辑是否易于跟随？文件和函数的组织是否合理？
3. **架构** — 是否遵循了项目已有的模式和约定？模块边界是否清晰？抽象层次是否适当？
4. **安全性** — 输入是否经过校验？密钥和敏感配置是否安全存储？权限校验是否完整？
5. **性能** — 是否存在 N+1 查询？是否有无界操作或潜在内存泄漏？热路径是否有不必要的重复计算？

**问题分级**：
- 🔴 **Critical（必须修复）** — 会导致功能错误、安全漏洞或数据丢失
- 🟡 **Important（建议修复）** — 影响可维护性、性能或代码质量
- 🔵 **Suggestion（可选优化）** — 风格改进或锦上添花

**输出格式**：
```
## 代码评审报告

### 🔴 Critical
- `src/xxx/Foo.java:42` — [问题描述 + 修复建议]

### 🟡 Important
- `src/xxx/Bar.java:17` — [问题描述 + 修复建议]

### 🔵 Suggestion
- `src/xxx/Baz.java:88` — [优化建议]

### 总结
[整体评价与是否可合并的结论]
```
