在不改变任何行为的前提下，简化最近修改的代码（或指定范围），提升可读性与可维护性。

1. **阅读项目约定** — 查看 CLAUDE.md、LINGMA.md 或项目 README，了解代码风格规范
2. **确定目标范围** — 默认为最近变更的代码；若用户指定了更大范围，则以用户指定为准
3. **理解再动手** — 在修改前，完整理解代码用途、调用方、边界情况和现有测试覆盖
4. **识别简化机会**：
   - 深层嵌套 → 提前返回（guard clause）或提取辅助方法
   - 过长函数 → 按职责拆分
   - 嵌套三元表达式 → 改写为 if/else 或 switch
   - 模糊命名 → 替换为表达意图的名称
   - 重复逻辑 → 抽取为共享函数
   - 死代码 → 确认无引用后删除
5. **逐步应用** — 每次只做一处简化，随即运行测试，确认绿色后再做下一处
6. **最终验收** — 所有测试通过、构建成功、diff 清晰可读

**回滚原则**：若某次简化导致测试失败，立即回滚该变更并重新分析，不要带着失败测试继续推进。
