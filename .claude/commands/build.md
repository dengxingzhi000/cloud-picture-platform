按照测试驱动开发（TDD）方式，逐任务增量实现功能，每步可验证、可提交。

从计划文件（tasks/plan.md 或 tasks/todo.md）中取出下一个待办任务，按以下步骤执行：

1. **读取验收标准** — 理解该任务的完成条件
2. **加载相关上下文** — 阅读已有代码、接口定义、类型声明和项目约定
3. **写失败测试（RED）** — 针对期望行为先写断言，此时测试必须失败
4. **最小实现（GREEN）** — 只写刚好能让测试通过的最少代码
5. **回归验证** — 运行完整测试套件，确认无已有测试被破坏
6. **构建验证** — 执行构建命令，确认编译通过
7. **提交** — 使用描述性 commit message（遵循 Conventional Commits 规范）提交
8. **标记完成** — 在 tasks/todo.md 中将该任务标为已完成，继续取下一个任务

**遇到失败时**：
- 测试失败：定位根因，不要修改测试来迁就实现
- 构建失败：检查依赖、类型、编译错误后再继续
- 回归失败：说明本次改动影响了已有功能，需在当前步骤内修复
- 若任何步骤持续阻塞，记录阻塞原因并报告给用户，不要跳过
